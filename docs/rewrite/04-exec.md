# 04-exec — Execution plan for the IPC contract and events

Turns [04-ipc-and-events.md](04-ipc-and-events.md) into ordered milestones. Dense by
design: every line is an instruction or a decision. Read it fully before touching the
repo, work the milestones in order, and end each one green and in one commit.

- **Written:** 2026-11-11, after 03-exec landed (`e81a484` on `rewrite/03-data-model`).
- **Effort:** ≈4.5 ideal days. Covers the backend and `lib/ipc` halves of 06 phases 3–4
  (every read and write command, events, invalidation, mock). After this plan, 08-exec
  only builds screens on top of `commands.*`, `queries.ts` and the mock.
- **Read first:** 04 (all), 03-exec §9 (handoff) and §10 (log), 02 §Request flow, 05
  §Backend extension points, 07 §Rust "Command tests", and the existing
  `desktop/src-tauri/src/commands/settings.rs` (the pattern to copy).

## 1. Scope

**In:** domain commands and DTOs for contacts, campaigns, send batches, imports, activity
(audit), global search and `app_backup_create` · new `DomainEvent` variants and their
emission after commit · import progress events · picked-file allowlist · batched campaign
stats · the prepare-send audience guard · `lib/ipc` query keys, query factories and event
invalidations · an in-memory domain mock for `pnpm dev:web` and Playwright.

**Out (owner):** screens, forms, wizard, URL state and progress UI (08-exec) · import undo,
configurable identity, bulk conflict actions (phase 5) · FTS5 search, virtualization and
perf budgets (phase 6) · backup *restore* from the UI (phase 7; it needs an app restart) ·
feature-flag gating of commands (no flagged feature exists yet) · `OperationFailed`
emission (no background job exists; the variant stays reserved). Do not add frontend
feature folders, and do not run `pnpm gen` in the real tree: it would create placeholder
routes and core modules.

## 4. Facts that will bite

1. **Stale generator output.** `desktop/src/lib/ipc/mock.ts` still lists a `demo` feature
   and a `demo_list` handler from a real `pnpm gen` run, so the mock's `app_features`
   advertises a feature that does not exist. Remove both in M0 and keep the `@gen:`
   markers.
2. **`DomainEvent`'s `rename_all = "camelCase"` renames variants, not fields.**
   `ImportProgress { progress_id }` would go out as `progress_id`. Put
   `#[serde(rename_all = "camelCase")]` on every variant that has multi-word fields, and
   test the JSON keys (M0).
3. **Deserialization failures never become `AppError`.** A bad enum string or a missing
   field makes Tauri reject before the command body runs, and `client.ts` turns that into
   `INTERNAL`. So: make every field that has a sensible default `Option`, never parse
   enums by hand, and do semantic checks in `TryFrom<Request>`, which returns
   `Validation` with a field name.
4. **Generic `PageDto<T>` export.** rc.28 should emit `PageDto<T>` as a TS generic. If the
   output is wrong or not deterministic, replace it with concrete per-item structs
   generated by a `page_dto!` macro. Inspect `bindings.ts` after M0.
5. **Campaign list N+1.** `CampaignService::list` returns campaigns without stats, and
   `stats(id)` costs three queries, including a `NOT EXISTS` scan over contacts. A
   500-row page would run 1 500 queries. M2 adds a batched `stats_for(ids)`.
6. **Preview/send race.** The UI previews `unsent`, but `prepare_send` reselects at commit
   time, so a contact added in between would reach the clipboard unpreviewed (06 phase 4
   requires "exactly the previewed set"). M2 adds `expectedCount`: on a mismatch the
   command returns `Conflict` and rolls back before the clipboard is touched.
7. **Arbitrary file reads.** `imports_inspect`/`imports_preview` take a path from the
   webview and send cell contents back. Accept only canonical paths that
   `imports_pick_source` returned in this process (M3). Drag-and-drop (08) must register
   paths on the Rust side as well.
8. **No headers without a complete mapping.** `mapping::resolve` fails with
   `Validation{field:"mapping"}` when the suggestion is incomplete, so a preview-only flow
   can never show the columns to map. M3 adds `imports_inspect`, which creates no draft.
9. **Draft pile-up.** Every re-preview (after a mapping or scope change) creates a draft,
   and `pending_imports` keeps counting them. `imports_preview` takes `replacesBatchId?`
   (M3).
10. **`read_source` blocks** for up to a 20 MiB workbook. Run it in
    `tauri::async_runtime::spawn_blocking`, never on the async runtime.
11. **`ImportPreview` has no removal list**, only `summary.removed`. A roster import must
    show *who* will be marked removed before apply, so M3 adds
    `removals: Vec<PlannedRemoval>` to `ImportPreview`.
12. **Mocked events.** With `shouldMockEvents`, `listen`/`emit` never reach the
    `plugin:event|*` handlers, so those handlers and the test that checks them become
    dead. Update both in M5.
13. **specta `_Serialize`/`_Deserialize` splits** appear for types used in both
    directions. Keep request and response structs separate (enums are the exception) so
    the TS stays readable.
14. Core `ImportPhase` is `reading|matching|applying` (04 says `parsing`). Use the core
    names.
15. Identity keys are internal. No DTO exposes `identity_key`, `file_hash` or
    `source_path`.

  Add `AppState.picked_sources: Mutex<HashSet<PathBuf>>` (std `Mutex`, never held across
  `.await`).
- `commands/dto.rs`:
  - `dto_enum!(ContactStatusDto <=> ContactStatus { Active, Removed, Archived })` builds
    the DTO enum (`Serialize, Deserialize, specta::Type, Clone, Copy, PartialEq`) plus
    both `From` impls. The serde casing must equal the core enum's (`snake_case` for
    `string_enum!` types; `camelCase` for `ContactSort`/`AudienceFilter`). Cover
    ContactStatus, ContactSource, ContactSort, EmailChangeReason, CampaignStatus,
    AudienceFilter, SendRecordStatus, ImportStatus, ImportScope, SourceKind,
    ConflictKind and ImportPhase.

  - `fn page(limit: Option<u32>, offset: Option<u32>) -> PageRequest` (normalized).
  - `fn search_term(Option<String>) -> Result<Option<String>, AppError>` (trim; blank →
    None; > 200 chars → `Validation{field:"search"}`).
  - `pub struct Emitted<T> { pub value: T, pub events: Vec<DomainEvent> }` and
    `fn finish<T>(app, state, Emitted<T>) -> T`, which emits in order.
- **Command shape (every module):** the `#[tauri::command]` wrapper does only
  `state.services()?` → `body(services, request).await` → `finish`. The body is
  `pub(crate) async fn` and takes `&Services` (plus `&PickedSources`/`&DataPaths`/
  `&dyn ProgressSink` when needed) and a request struct. Reads return
  `Result<Dto, AppError>`, writes `Result<Emitted<Dto>, AppError>`. Because an `Err`
  carries no events, emission after commit holds by construction. Every command takes a
  single `request` argument, except commands with no input.
- `events.rs`: add `ContactsChanged {}`, `CampaignsChanged {}`, `SendBatchesChanged {}`,
  `ImportsChanged {}`, `ImportProgress { progress_id: String, phase: ImportPhaseDto,
  processed: u64, total: u64 }` and `ImportFinished { batch_id: i64, status:
  ImportStatusDto }`, each with per-variant camelCase (§4.2). Derive `PartialEq` for
  tests. Remove the "later exec plans add" comment.
- `commands/testing.rs`: `async fn harness() -> Harness { db: TempDb, services: Services,

### M2 — Campaigns and send batches (≈1 d)

Core/store first:
- `CampaignRepository::stats_for(&self, ids: &[i64]) -> CoreResult<HashMap<i64,
  CampaignStats>>` in three queries: (1) active/removed totals `GROUP BY status`;
  (2) `send_batches ⋈ send_records` grouped by `campaign_id` → `sent`,
  `MAX(b.created_at)`; (3) the same join `⋈ contacts` on `contact_id`, grouped by
  `(campaign_id, c.status)`, `COUNT(DISTINCT c.id)`. Then `unsent = active_total −
  active_with_record`, `removed = removed_total − removed_with_record`, `total = sent +
  unsent`. Use `IN` with repeated `?`, and return an empty map for empty `ids` with no
  query. Add `CampaignService::list_summaries(&CampaignQuery) ->
  Page<CampaignSummary>`.
- `SendService::prepare_send(campaign_id, expected_count: Option<u64>)`: after
  `begin_batch`, if `Some(n)` and `pending.emails().len() != n`, drop pending and return
  `Conflict("The audience changed since you reviewed it. Review it again.")` (§4.6).
  Update existing callers (`seed_demo.rs`, `weasel-store/tests/{sends,campaigns}.rs`,
  `weasel-import/tests/apply.rs`) to pass `None`, and add a core test for each branch.

`commands/campaigns.rs` (id `campaigns`, events `campaignsChanged`):
`campaigns_list {status?, search?, limit?, offset?}` → `PageDto<CampaignSummaryDto
{campaign, stats}>` · `campaigns_get {id}` → `CampaignDto` · `campaigns_create {name,
description?, subject?, body?}` · `campaigns_update {id, version, …?}` ·
`campaigns_set_status {id, version, status}` · `campaigns_delete {id, version}` → all
writes emit `CampaignsChanged` · `campaigns_stats {id}` → `CampaignStatsDto` ·
`campaigns_audience {campaignId, filter, search?, limit?, offset?}` →
`PageDto<AudienceMemberDto>` (snapshot rows, not `ContactDto`) ·
`campaigns_prepare_send {campaignId, expectedCount?}` → `PreparedSendDto {batchId,
recipientCount, emails}` and emits `SendBatchesChanged` + `CampaignsChanged`.

`commands/send_batches.rs` (id `send-batches`, events `sendBatchesChanged`):

`send_batches_get {id}` → `SendBatchDto` · `send_batches_recipients {id, search?, limit?,

## 9. Handoff to 08-exec

Screens consume only `commands.*`, `queries.ts` factories and `call()`. Map
`IpcError.code` like this: `VALIDATION` → `fieldError(err, field)` on the form ·
`CONFLICT` → the "changed elsewhere, reload" dialog (for prepare-send: "review again") ·
`IO` + `retryable` → a retry toast · `INTERNAL` → a toast with `details.logId`. The import
wizard runs `pick_source` → `inspect` (mapping UI from `headers`/`suggestedMapping`, sheet
switch re-inspects) → `preview` (pass `progressId = crypto.randomUUID()` and
`replacesBatchId` on re-preview; show `removals` and `warnings` before apply) → review
(`sample`, then `plan_rows` for more) → resolve `conflicts` → `apply`/`discard`. Progress
comes from `startEventBridge`'s `onEvent`. Send flow: `campaigns_audience{filter:"unsent"}`
+ `campaigns_stats` → confirm → `campaigns_prepare_send{expectedCount: stats.unsent}`.
Drag-and-drop import must add the dropped path to `picked_sources` in a Rust-side
drag-drop handler. Contacts list URL state maps 1:1 onto `contacts_list`'s request.
